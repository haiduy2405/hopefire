# Gamepad Support Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans. Steps use checkbox syntax.

**Goal:** Whole game playable with an XInput pad (Flydigi Vader 4 Pro) without breaking mouse/keyboard/touch.
**Architecture:** One new classic script `src/pad.js` (after `ui.js`, before `title.js`) polls the standard Gamepad API each frame and only *synthesizes existing handlers* (`el.click()`, `togglePause()`, `R.mark=…`); no gameplay logic duplicated. Pure helpers (`padNextFocus`, `padGlyphs`) are exposed on `window` for headless tests.
**Tech Stack:** vanilla JS, Gamepad API, Playwright headless with an injected fake `navigator.getGamepads`.
**Spec:** `docs/superpowers/specs/2026-11-18-gamepad-design.md`

## Global Constraints
- No build step, no deps; keep script order (add `pad` after `ui`, before `title`).
- New meta/settings fields only via `defMeta()`/settings defaults in `src/core.js`, never rename keys (`meta.set.rumble`, default true).
- English UI text only. Pad input never changes balance; no pad connected ⇒ zero behaviour change.

## Review Focus
- Pad connected mid-run / disconnected mid-crate: focus must not get stuck; game must remain mouse-playable.
- Modal opens/closes (crate cards, lock, loadout, einfo, tip) – focus must move into the topmost modal and return afterwards.
- Held buttons / stick drift: repeat-rate limited, deadzone 0.5, one action per press.
- Mouse/keyboard use after pad use hides focus ring and ignores stale pad state.
- Paused / userPause / CUT (cutscene) states: A skips cutscene only when skip is allowed; no marking while paused.
